# Create PR

## 실행 주체

PR 생성 작업은 반드시 서브 에이전트가 수행한다. 메인 에이전트가 이 스킬을 읽으면 서브 에이전트 하나에 위임하고 결과를 기다린다. 위임할 때 이 SKILL.md의 절대 경로, 저장소 경로, 사용자 요청, 작업 범위, 알려진 검증 결과와 승인 범위를 전달한다. 서브 에이전트는 이 스킬을 직접 읽고 실행하며 다시 위임하지 않는다. 메인 에이전트는 반환된 PR 링크와 핵심 결과를 사용자에게 전달한다.

서브 에이전트 기능을 사용할 수 없으면 직접 PR을 생성하지 말고 제한을 알린다. 이 스킬은 역할을 지시하며 런타임 접근 권한을 강제하는 설정은 아니다.

## 템플릿 선택

명시적인 사용자 언어 지정이 있으면 이를 우선한다. 그 외에는 대상 저장소의 원격 주소를 확인한다. HTTPS/SSH URL의 host와 owner/repo를 비교하고 `.git` 접미사와 끝 슬래시를 제거한다.

- 원격 중 하나가 `github.com/hong-s-i/react-component-generator`이면 [한국어 템플릿](references/pr-template.ko.md)을 읽고 PR 제목과 본문을 한국어로 작성한다. 경로가 바뀌거나 worktree를 사용해도 같은 기준을 적용한다.
- 그 외 저장소에서는 [영어 템플릿](references/pr-template.en.md)을 읽고 제목과 본문을 영어로 작성한다.
- 원격 주소를 확인할 수 없을 때만 저장소 루트가 `C:\Users\student\Desktop\react-component-generator-main`과 일치하면 한국어, 그 외는 영어를 사용한다. Windows 경로는 대소문자 차이를 무시한다.

선택한 템플릿만 읽는다. 저장소의 필수 PR 항목이 있으면 선택한 언어로 함께 반영한다. 저장소에 템플릿 파일을 설치하거나 기존 템플릿을 덮어쓰지 않는다.

## PR 준비와 생성

1. 대상 저장소의 AGENTS.md를 읽고 Git 상태, 현재 브랜치, 원격, base 브랜치, 기존 PR을 확인한다. base는 사용자 지정 또는 저장소 기본 브랜치를 사용한다. PR 대상 저장소/브랜치를 결정할 수 없으면 필요한 정보만 요청한다.
2. base와 head 사이의 커밋과 전체 diff를 읽어 실제 변경을 설명한다. 작업 트리의 미커밋 변경을 PR에 포함된 것으로 설명하지 않는다. PR 요청만으로 미커밋 변경을 임의로 커밋하거나 관련 없는 작업을 포함하지 않는다. 요청 범위의 변경이 미커밋 상태뿐이면 상태를 알리고 커밋 범위를 확인한다.
3. 기존 검증 결과를 확인하고 저장소 지침상 필요한 검사를 수행한다. 실행하지 않은 검사, 실패한 검사, 남은 제한을 사실대로 기록한다. 검사 실패를 고치기 위한 무관한 코드 수정은 하지 않는다.
4. 선택한 템플릿을 실제 내용으로 채운다. 문제와 변경 후 동작을 먼저 설명하고 리뷰에 필요한 구현·검증·위험만 적는다. 예시 안내문은 제거하고, 해당하지 않는 선택 항목은 생략한다. 근거 없는 성공 주장이나 이슈 번호를 만들지 않는다.
5. 연결된 GitHub 도구가 생성·조회 기능을 제공하면 우선 사용한다. 그렇지 않으면 인증된 `gh`를 사용한다. PR 생성 요청은 선택한 작업 브랜치의 필요한 일반 push와 PR 생성을 포함하므로 별도 승인을 반복 요청하지 않는다. 보호 브랜치 직접 push, force push, 이력 재작성, 병합은 포함하지 않는다. 로컬 head가 기본/보호 브랜치라면 저장소 지침에 맞는 작업 브랜치를 만들어 사용한다(기본 접두사 `codex/`).
6. 같은 head/base의 열린 PR이 있으면 새 PR을 만들지 않고 URL과 상태를 반환한다. 기존 PR 수정은 사용자 요청 범위에 있을 때만 한다. 새 PR 생성 직전에 대상과 diff를 다시 확인하고 필요한 브랜치를 push한다. 사용자가 지정한 draft 여부를 따르고, 지정하지 않으면 일반 PR을 만든다.
7. `gh`로 여러 줄 본문을 전달할 때 임시 UTF-8 파일과 `--body-file`을 사용한다. 생성 결과의 URL, base/head, 제목을 조회해 확인한다. 생성 응답이 불명확하거나 시간 초과가 발생하면 기존 PR을 조회한 뒤 재시도를 판단한다. 인증·권한 문제는 반복 시도하지 말고 필요한 조치를 알린다.

## 결과 보고

PR URL, 대상 브랜치, 선택 언어, 검증 요약과 남은 제한을 메인 에이전트에 반환한다. 실패한 경우 완료된 단계와 실패 원인을 구분하고 생성 성공을 주장하지 않는다.
